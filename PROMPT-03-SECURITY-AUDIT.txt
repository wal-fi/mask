Assuma agora o papel de um engenheiro de segurança tentando quebrar o AI Data Masking Gateway.

Não implemente novas funcionalidades inicialmente.

Analise o código existente procurando formas de fazer dados originais chegarem ao cliente MCP.

Teste especialmente:
- SELECT *
- aliases
- JOINs
- UNION
- CTE
- subqueries
- views
- funções
- casts
- case variations
- nomes com prefixos/sufixos
- exceptions
- NULL
- erros
- logs
- metadata
- SQL injection
- tentativa de alterar regras pelo MCP

Para cada vulnerabilidade encontrada:
1. explique o ataque;
2. mostre onde ocorre;
3. classifique severidade;
4. proponha correção;
5. crie teste de regressão.

Não considere o sistema seguro apenas porque os testes existentes passam.
